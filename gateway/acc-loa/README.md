# ACC LOA Google Workspace Gateway (staged, not deployed)

Owner of ACC remains existing GitHub/Vercel/Supabase. Deploy the isolated Apps Script project as ipgs.admission@innovative.edu.my. Do not modify the legacy Apps Script or acceptance signing service.

1. Create a standalone Apps Script project "IUC ACC — Google Workspace Gateway" while signed in to IPGS Admission. If an approved IPGS Shared Drive is available, use it and confirm the deployer has rights; otherwise retain this project in the institutional account and document editor/ownership access. Do not add a personal Gmail owner.
2. Copy Code.gs and the appsscript.json manifest. Enable showing the manifest under Project Settings. Advanced services Docs, Sheets and Gmail must be present. Run verifyGatewaySetup from the editor as IPGS Admission, approve Google permissions, and verify the returned health data. No mail or workflow mutation is performed by this function. Review scopes (Drive, Docs, Sheets, Gmail send, user email) and Workspace policy. Do not circumvent admin restrictions.
3. Generate a new 32-byte random secret locally (64 lowercase hex characters). Save it directly in Script Properties ACC_GATEWAY_SECRET and Vercel ACC_LOA_GATEWAY_SECRET (sensitive, production). Never paste it in chat or commit it. Set ACC_GATEWAY_WRITE_ENABLED=false. Leave ACC_GATEWAY_CC_ROUTING_JSON unset until exact CC policy is approved; configure the same JSON in ACC_LOA_CC_ROUTING_JSON on Vercel.
4. Deploy a new web app, Execute as me (IPGS Admission), Anyone only if organization policy permits this external server-to-server web app. Endpoint must reject unsigned requests; do not make generic Google proxy operations available. If this deployment option is unavailable, stop and use an administrator-approved integration. The script validates the execution identity, request HMAC, timestamp, nonce and operation, checks the authoritative application row and folder, allows only the four original templates and LOA workflow columns, validates recipient and CC, and marks uncertain delivery for manual review. Cache nonce checking is best-effort, not a durable idempotency ledger; ACC's unique ledger and workflow delivery state provide durable duplicate protection. Script Properties are accessible to project editors; only trusted maintainers should be editors.
5. Configure Vercel ACC_LOA_TRANSPORT=gateway, ACC_LOA_GATEWAY_URL=the new /exec URL, ACC_LOA_GATEWAY_SECRET as sensitive. Keep ACC_LOA_GATEWAY_READY=false, ACC_LOA_NATIVE_READY=false and ACC_LOA_ACCEPTANCE_BACKEND_READY=false. Verify signed health and invalid authentication. Health verifies template and spreadsheet access but does not establish write or send permission.
6. Use a dedicated synthetic applicant and authorized test mailbox with separate test folder/approved CC; ensure it is not a real student. Validate four actual PDFs, MIME and Gmail message ID, acceptance token, workflow transitions and recovery after uncertainty. Confirm execution budget/timeout and quotas. Activate writes only during controlled UAT; do not activate live ACC until signing-only acceptance backend has passed live UAT and legacy credential-text policy and CC routing are approved.
7. Source files remain in ACC GitHub; actual Google deployment and editor access must be documented and tested. The source's direct OAuth transport remains available but is not required for gateway mode. No generic web access, no applicant lists returned and no credentials or acceptance tokens logged.

The code is staged and regression-tested locally with mocks; no Google deployment or real message has been performed.
